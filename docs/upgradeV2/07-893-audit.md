## 🟡 What's missing or imprecise

### 🟡 1. The actual trigger is unnamed — `mergeEventDraft` never returns a stable reference (CRITICAL LEAD)

The React error text is specific: *"setState inside useEffect … one of the dependencies changes on every render."* The bridge passes `draft` as **controlled state** to `useCoAgent`, whose internal sync effect setStates whenever the `state` reference changes. Now look at how `draft` is produced (`src/lib/types/event-draft.ts:38`):

```ts
export function mergeEventDraft(current, patch) {
  return EventDraftStateSchema.parse({ ...current, ...patch });  // ← NEW object every call
}
```

`zod.parse()` constructs a **fresh object every time** — even when `patch` is empty or identical. So every `setState`/agent-stream tick *may* yield a new `draft` reference → `useCoAgent`'s sync effect sees a changed dependency → setState again → new reference → loop, until React's depth guard trips at 50. **Prime hypothesis for A3 — not confirmed until bisect probes pass.**

**Fix lead to add (for the eventual fix ticket):** make `mergeEventDraft` return `current` unchanged when the parsed result is deep-equal (referential stability on no-op), OR memoize the `state` passed to `useCoAgent`, OR drop the redundant `draft`-keyed subscription (see #2). Any one likely silences the loop without touching the v2 path.

### 🟡 2. `draft` is shared on two channels, both keyed on `[draft]`

The bridge exposes `draft` via **both** `useCoAgent({ state: draft })` (agent working-memory sync) **and** `useCopilotReadable({ value: draft }, [draft])` (LLM context). Different channels, but both re-register every time the unstable `draft` reference changes — amplifying the re-render pressure. The investigation should test each in isolation (A3 hints at this; make it explicit: disable `useCopilotReadable` alone, then memoize `useCoAgent` state alone, and watch which kills the loop).

### 🟡 3. A4 treats `thought_signature` as separable — evidence shows it interleaved

A4 says "separate Gemini `thought_signature` / `mastra_workspace_list_files` from React loop." But in the evidence `consoleErrors[]`, the max-update-depth bursts and the `INCOMPLETE_STREAM` agent error are **interleaved**. They may be coupled: an errored/retried agent stream re-pushes state, and with an unstable `draft` reference each push re-triggers the loop. **Refine A4:** don't just *separate* them — test *causation* (does suppressing the agent error reduce the loop bursts?). They might share a root.
