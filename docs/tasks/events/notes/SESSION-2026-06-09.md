## SAN-492 · EVT-033 — Event Venue + Offerings Schema (the core decision)

**Model (final):** reuse the shipped partner stack.
- **EXTEND** `partner_locations` — `accepts_event_bookings`, `is_verified`, `capacity_seated/standing` (venue identity).
- **CREATE** `venue_event_offerings` + `venue_event_packages` (FK → `partner_locations`).
- **REUSE** `bookings` for proposals — `booking_type='event'` + `partner_status` CHECK `pending|approved|declined` are **already live**; `bookings_update_partner_member` gives partner/Patricia approval; `is_admin()` policy added for the admin queue.
- **Untouched:** `event_venues` (ticketed-event rooms), `venue_booking_requests` (café/table only).
- **Do NOT create:** `partner_venues`, `venues`, `event_venue_bookings`.

**Why:** the prior `partner_venues` draft duplicated the partner stack shipped 2026-06-06 (`ptr001–014`). `partners.type` enum already has `venue`; `bookings.booking_type` already has `event`. Blockers B1 (duplicate master), B2 (RLS owner), B3 (`venue_booking_requests` constraint surgery) all dissolved.

**Readiness: 88/100 (B+)** · 🟢 GO for migration branch · 🔴 NO-GO for prod apply until human ERD sign-off + `get_advisors`.

**Dry run (rolled-back transaction):** full migration executed against live schema with **no errors**, then `ROLLBACK` — confirmed nothing persisted (`venue_event_offerings/packages`, new columns, policies, function all absent on live). Verified helper name `update_updated_at()` (not the assumed `set_updated_at`).
