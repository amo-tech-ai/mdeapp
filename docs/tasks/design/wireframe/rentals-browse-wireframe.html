/rentals — catalog wireframe & component spec

Build-ready blueprint for /rentals (today: redirects to /chat — this is the catalog that replaces the stub). Persona: Camila, apartment seeker. Applies the D-05 discovery shell (list │ map split) to the rentals vertical. Each band = layout left, component + notes right.

REAL-011 · SAN-478 · D-09 list + map split CTA = Schedule viewing (NOT external OTA) teal = interactive · gold = AI EN only · Phase 1

Global layout rules

  • Container: full-bleed split — grid lg:grid-cols-[1fr_minmax(420px,0.9fr)]; list scrolls, map sticky
  • Card system: reuse the shared <VenueCard> (D-08 / SAN-574) in its rental skin — do not rebuild
  • Money honesty: price = COP/month, total framing; no hidden fees (anti-scam trust)
  • Images: pale-teal placeholder (#E1F6F2) → real photos via /api/places/photo proxy + blur-up
  • Hard rules: mapId on <Map>, X-Goog-FieldMask on every Places call
  • Primary CTA = "Schedule viewing" → HITL lead (/api/leads/schedule-viewing), never an external listing link
  • A11y/perf: skeleton cards on async; prefers-reduced-motion on pin animations; focus ring on cards
  • Data: /api/rentals/search (Mastra tool → Supabase); filters drive querystring
