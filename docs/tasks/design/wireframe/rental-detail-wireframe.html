/rentals/[id] — detail wireframe & component spec

Build-ready blueprint for the rental detail page (opens from a RentalCard "Details" or pin). Persona: Camila. The conversion goal is one action: Schedule a viewing (HITL lead) — never an outbound OTA link. Full page on desktop, full sheet over /chat on mobile.

REAL-012 · SAN-479 · D-09 photos on open only (cost) CTA = Schedule viewing → leads EN only · Phase 1

Global layout rules

  • Two-col: content left, sticky booking card right (grid lg:grid-cols-[1fr_320px])
  • Photos fetched on open only (Places photo cost) via /api/places/photo proxy + blur-up
  • Price: COP/month, total-honesty; show what's included (admin/services) — anti-scam
  • AI insight = grounded summary (gold ✦); never invented amenities
  • Hard rules: location map needs mapId; any Places call needs X-Goog-FieldMask
  • Primary CTA: Schedule viewing → renderAndWaitForResponse HITL → /api/leads/schedule-viewing
  • A11y: gallery keyboard-navigable + alt text; sticky CTA reachable; focus-visible rings
  • Mobile: sticky bottom CTA bar (price + Schedule viewing)
