#### What Belongs in Supabase Relational Tables

* **Core Geometries & Locations:** Store exact latitude, longitude, and geographic point primitives (`geography(Point, 4326)`) alongside neighborhood spatial polygon boundaries to enable precise spatial filtering.
* **Telemetry & Quantitative Metadata:** Store exact opening hours, verified WiFi speeds (`integer`), price levels, review counts, and specific feature checkboxes (`has_outdoor_seating`, `is_pet_friendly`).
* **Source Citation Registers:** Track original source domains, target reference URLs, and confidence ratings to support clean attribution.

#### What Belongs in `pgvector` Embeddings

* **Multi-Vector Vibe Profiles:** Store dense vector representations (1536 dimensions) generated from descriptive text blocks covering design styles, sensory details, and interior character (e.g., *"calm minimalist specialty café with hanging greenery and quiet background music"*).
* **Extracted Flavor & Product Profiles:** Store embedded text capturing roasting philosophy and specific bean characteristics (e.g., *"experimental anaerobic fermentations with bright citrus notes and light roasts"*).
* **Unstructured Customer Sentiment:** Store unified summaries of customer reviews that capture overall consensus descriptions.

#### What Should Become AI Summaries

* **The Consensus Summary Component:** A short, zero-hallucination paragraph generated by passing verified customer quotes through Gemini 3.5 Flash using structured JSON schemas to outline exact expectations for the venue.
* **Contextual Recommendation Snippets:** Real-time sentences explaining exactly why a café matches a user's search (e.g., *"We recommend this spot because it matches your preference for fast WiFi and single-origin pour-overs in a quiet setting."*).

#### What Should Become Ranking Signals

* **The Curation Density Vector:** A computed multiplier based on how many independent expert sources highlight the establishment.
* **The Structured Capacity Score:** A dynamic weight that combines verified utility values (e.g., table size, power outlet access, connection stability) to score suitability for working.

#### What Should Become Standardized Tags

* **The Functional Amenity Matrix:** Relational boolean tags used for hard filtering options (e.g., `AC`, `Parking`, `Vegan-Options`, `Fiber-WiFi`, `Ergonomic-Seating`).
* **The Style Taxonomy:** Category tags used to power the recommendations interface (e.g., `Third-Wave`, `Brunch-Focus`, `Hidden-Gem`, `Social-Hub`).

### 4. Final Platform Strategy & Deliverables

#### Schema Design Recommendation

Implement a relational database structure where the core identity records remain protected from textual updates, and vector targets are split into separate rows by functional scope (`vibe`, `coffee`, `utility`). This allows for targeted similarity weighting at runtime.

#### Vector Strategy

Avoid running vector queries across messy, unformatted blog crawls. Instead, use an intermediate Mastra data preparation step to clean the data. The LLM processes source inputs, removes repetitive text, updates out-of-date information, and generates clean, structured summary blocks. These polished descriptions are then converted into vectors using `text-embedding-3-small`, creating clean, high-performance index points.

#### Ranking Engine Implementation Strategy

Construct a comprehensive scoring model that calculates the final rank by combining multiple factors rather than relying solely on reviews. Use the following formula to weigh results:

* **30% Editorial Curation Density:** Prioritizes recommendations from verified expert platforms over mass traveler reviews.
* **25% Semantic Vector Match:** Measures how well the venue's profile aligns with the specific keywords and intent of the user's search.
* **15% Verified Utility Telemetry:** Scores the venue based on essential practical needs, such as network speed and power outlet availability.
* **15% User Persona Correlation:** Adjusts results to align with the user's active travel profile (e.g., remote worker, coffee purist, or foodie).
* **15% Normalized Google Maps Score:** Integrates a baseline rating using an exponential decay function to ensure high-volume review data is factored in fairly.

#### Source Attribution Strategy

Maintain transparency and user trust by avoiding unverified text outputs. Every qualitative highlight or summary card must display a clear link pointing directly to its original source publication (e.g., `[ Eater Specialty Guide ]` or `[ Medellín Guru Review ]`). This approach builds platform authority and provides an audit trail that keeps information clean and reliable.

#### Image Display Strategy

Avoid generic, low-quality images. The frontend interface should sort image carousels using explicit metadata classification tags (`#interior`, `#workspace`, `#brunch`, `#coffee`). This ensures that when a user searches for a place to work, the interface highlights photos of wide tables and power layouts rather than close-up product shots.

#### Semantic Search Strategy

Deploy a hybrid search architecture that utilizes the efficiency of the database environment. Use structured SQL fields to apply hard filters first (e.g., separating locations like `neighborhood = 'laureles'`), and then apply the `pgvector` cosine distance calculation on the filtered subset. This keeps response times fast and accurate.

#### Deep Personalization and AI Concierge Ideas

* **The Dynamic Persona Switch:** Allow users to adjust their search focus instantly with simple interface toggles. Switching from "Work Focus" to "Coffee Enthusiast" dynamically updates the ranking formula, elevating places like *Semilla* for productivity or *Rituales* for specialty coffee.
* **The "Similar to" Recommendation Function:** Create a recommendation loop using vector comparisons. When a user marks an establishment like *Pergamino* as a favorite, the system calculates vector distances to highlight alternatives with matching physical layouts and community profiles across other neighborhoods.
